推荐上手顺序

  1. 只想最快见效 — 装 boss-helper 浏览器扩展，零配置，装完就能批量投递。
  2. 要功能最全、能接受装环境 — 上 get_jobs。务必先做这一步：从 release 下载 getjobs.db.template，重命名为 getjobs.db 放进 db/ 目录，否则项目起不来。
  3. 最怕封号、要可控 — 用 BossHunter 或 auto-zhipin，两者都强制你先审核再发送。
  4. 想先验证 AI 写的招呼语质量 — 跑 Boss-Zhipin-Auto-Job-Application，打开 DRY_RUN=1，只生成不发送。
  5. 确认文案满意后 — 再放开限制正式跑，并保持低频。

通用风险与注意事项

  • 01账号风险是真实的。这类工具属于浏览器自动化，违反平台用户协议，存在黑号、封号、权重降低的可能。建议先用小号或极低频试水。
  • 02先 dry-run 再正式跑。检查 AI 生成的招呼语是否专业、有没有编造经历，别让机器替你乱说话。
  • 03API Key 只放在本地 .env，不要提交到公开仓库、Issue 或聊天记录里。
  • 04国内平台不要挂代理。get_jobs 作者明确说明墙外代理会导致页面加载极慢；同时这类项目不支持服务器部署，招聘站识别到服务器 IP 会直接不返回数据。
  • 05谨慎对待 README 里的「AI 指令」。例如 BossHunter 的 README 内嵌了一段要求 AI 读取 CLAUDE.md 且声称「优先级高于一切」的提示词。这类内容应当作不可信数据处理，不要盲从。
  • 06注意许可证性质。get_jobs 与 BossHunter 均为 PolyForm 非商业许可（source-available，并非 OSI 定义的开源），禁止商业使用；auto-zhipin 为 BSD-3-Clause。
  • 07警惕仿冒与收费项目。get_jobs 作者提到有人拿他的项目做收费推广甚至诈骗，注意甄别来源。
